## 1. 产品愿景

「飞鸿踏雪泥,泥上偶然留指爪,鸿飞那复计东西。」

雪泥是一个主打**阅后即焚、不留痕迹**的实时聊天工具。每一条消息都像落在雪上的一枚鸿爪——你看过它,雪便化去,了无痕迹。我们承诺:**服务器看不见内容,聊天结束不留档案。**

### 核心价值主张
- **过目无痕** —— 消息焚毁后,任何一方设备与服务器均不保留。
- **只有你和对方能看见** —— 端到端加密,服务器只经手密文。
- **不需要信任平台** —— 安全性由密码学保证,而非"我们承诺不看"。

## 2. 目标用户与场景

| 用户 | 典型场景 |
|------|---------|
| 注重隐私的普通用户 | 不想让聊天记录被平台留存、被翻旧账 |
| 临时敏感沟通 | 传一次性的口令、地址、私密信息,用完即焚 |
| 记者 / 律师 / 敏感职业 | 需要"事后无可取证"的沟通渠道 |

**非目标**:本产品不追求做长期社交关系链、群聊社区、历史存档——那与"不留痕"的内核冲突。

## 3. 核心特性(MVP 范围)

### 3.1 三大焚毁机制(本项目核心)

#### ① 服务器零存储(Zero Storage)
- 服务器**仅做实时中转**,不写入任何数据库、日志、缓存。
- 消息在内存中经手一次,投递后立即丢弃。
- **核心约束:收发双方必须同时在线。** 任一方离线,消息(含文字与富媒体)**不排队、不落盘**,直接丢弃。服务器**不实现任何暂存队列**——这既是隐私承诺,也大幅简化后端。
- 关闭页面 / 会话即彻底消失,无历史记录接口。

#### ② 端到端加密(E2EE)
- 明文**永不离开**用户浏览器。
- 客户端加密 → 服务器只见密文 → 对端客户端解密。
- 密钥协商在两端之间完成,服务器**不掌握、不经手**私钥。
- 即使服务器被攻破或被要求交出数据,拿到的也只是无法解密的密文。

#### ③ 定时销毁(Timed Burn)
- 消息可设置存活时长(如 5s / 30s / 5min / 阅后即焚)。
- 到期后从收发双方界面与内存中**自动抹除**。
- "阅后即焚"模式:接收方查看后立即销毁,并可选通知发送方"已焚毁"。

### 3.2 会话机制(v0.2 定稿)

**身份模型:完全匿名,无登录、无注册。** 服务器不存任何账号/身份数据。可在进房时输入一个仅本地/会话内使用的临时昵称(不落盘),用于聊天窗区分「你/对方」。

**会话发起流程:**
1. 一方**创建房间** → 系统随机生成 **9 位房间号**(如 `123456789`)。
2. 创建者设置**进入口令**(用于派生 E2EE 密钥)。
3. 得到分享链接 `https://your-domain.example/123456789`(房间号在路径中,会发往服务器,仅用于路由/配对,不含密钥)。
4. 创建者**带外**(微信/口头等)把口令告诉受邀方——**口令永不发往服务器**。
5. 受邀方打开链接、输入口令 → 本地用口令派生出与创建者一致的密钥 → 进入聊天室。

- 密钥方案:**口令带外传 + 路径放房间号**。口令经 KDF(如 Argon2id,以房间号为盐的一部分)派生对称密钥;服务器只经手密文,永不接触口令与明文。
- 会话为临时性,**双方离开即销毁**(见 3.1 ③ 与 4)。

### 3.3 基础聊天能力(在线 WeChat 式体验)
- 实时**文字**消息收发(WebSocket)。
- **图片 / 语音 / 文件**收发:端到端加密后分块经服务器内存中转,**不落盘**;**要求收发双方同时在线**(离线不暂存,直接丢弃)。
- 消息默认**发送 5 分钟后自动销毁**(从收发双方界面与内存中抹除)。
- **退出聊天室 → 该端本地全部消息立即销毁**;双方均退出 → 会话彻底消失。
- 对方在线状态 / 正在输入提示(可选,注意不留痕原则)。
- 消息发送/焚毁的视觉反馈(呼应"雪化"的动效)。

## 4. 安全与隐私原则(不可妥协)

1. **零知识**:服务器对消息内容零知识,只经手密文。
2. **零存储**:不建历史库、不写业务日志、不做消息持久化。
3. **零信任平台**:安全由密码学保证,不依赖"平台承诺"。
4. **最小元数据**:尽量减少可关联到用户身份的元数据(IP、时间戳等按需最小化)。
5. **前向保密(目标)**:密钥定期轮换,历史消息不因密钥泄露而被回溯解密。

> ⚠️ 诚实边界:技术上不存在"绝对安全"。本产品在**内容层**做到服务器无法读取、聊天不留档;但**元数据层**(谁在何时连接了服务器)、**端点安全**(用户设备被入侵、截屏)不在密码学保护范围内。这些将在文档中如实说明,不做过度承诺。

## 5. 技术架构(概要)

```
┌─────────────┐        密文 over WSS        ┌─────────────┐
│  用户 A      │  ───────────────────────▶  │             │
│  React 客户端 │        (仅中转,不落盘)       │  Node 中转   │
│  本地加解密   │  ◀───────────────────────  │  服务器      │
└─────────────┘                             │  内存转发    │
                                            └──────┬──────┘
┌─────────────┐                                   │
│  用户 B      │  ◀────────────────────────────────┘
│  React 客户端 │        密文 over WSS
│  本地加解密   │
└─────────────┘
```

### 前端(React)
- 界面与交互、消息列表(仅存于内存,不写 localStorage)。
- 端到端加密/解密(Web Crypto API)。
- 定时销毁计时器、焚毁动效。

### 后端(Node.js)
- WebSocket 服务,负责建立 A↔B 的实时通道。
- **无数据库、无持久化日志**,仅内存中转。
- 房间/会话生命周期管理(内存态,会话结束即清)。

### 加密方案(待细化)
- 密钥协商:候选 X25519(ECDH)。
- 消息加密:候选 AES-GCM 或 XChaCha20-Poly1305。
- 均基于浏览器 Web Crypto / 成熟密码学库,不自造加密算法。

## 8. 附:命名由来

- **中文名「雪泥」**:取自苏轼《和子由渑池怀旧》"人生到处知何似,应似飞鸿踏雪泥"。鸿爪印雪、雪化痕消,天然贴合"阅后即焚、过目无痕"。
- **英文名「Thaw」**(融雪、消融):与中文意象首尾呼应——中文是落下的痕,英文是化去的过程。短、冷冽、独特,不易撞名。
- **Slogan**:见字如面,过目无痕 / Read it. Watch it thaw.
