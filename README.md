# 雪泥 · Thaw

> 见字如面，过目无痕。Read it. Watch it thaw.

> ⚠️ **重要声明**：本仓库为**开源技术参考实现**，仅供学习、研究与个人授权使用。**不提供、不运营任何面向公众的在线服务**；任何演示部署仅供作者及授权者内部使用，**不对外公开**。禁止用于任何违法用途，自部署者自负全部法律与运营责任。完整条款见 [`DISCLAIMER.md`](DISCLAIMER.md)。

一个不留任何痕迹的端到端加密即时聊天网站。服务器只经手密文、不落盘；消息定时自毁、退出即焚。双方带外（如微信/当面）约定同一「房间号 + 口令」，在首页填入即进入同一房间——不存在则自动创建、已存在则加入，无需区分谁是「创建方」，双方同时在线即可开始一段用完即化的加密对话。

## 特性一览

- **完全匿名，无登录**：约定房间号（支持中文词或 9 位数字）+ 口令，通过其它渠道带外发给对方。全程无账号、无 Cookie、无本地存储。
- **统一进房入口**：首页直接填「房间号 + 口令」即进——房间不存在则自动创建、已存在则加入；号+口令相符即进同一房间。想要高熵随机号/口令可点「随机生成」进创建页。
- **可重复进入**：只要房内还有一人在线，另一方（含刚刷新/断线的自己）用同一号+口令即可重新进房并重新握手，不会因一次刷新而永久失去房间。
- **端到端加密**：口令经 Argon2id 派生 + ECDH(P-256) 交换会话密钥，服务器只见密文；口令认证短串（SAS）防中间人掉包公钥。
- **收发双方必须同时在线**：不做离线暂存（服务器无消息队列，纯内存中转、零持久化）。
- **富媒体**：文字、图片、语音、视频、任意文件；截屏 Ctrl+V 贴图、拖拽发送、移动端相册/拍照/录音入口。文件下载走受控程序化触发（重封装为 octet-stream 强制「保存」），绝不导航到 blob URL，因而下载/打开附件不会卸载页面、不会误退聊天室。
- **三层焚毁**：消息定时自毁（默认 5 分钟；视频/音频为「时长 + 默认 TTL」，播放期间不倒计时、播完仍留完整设定时长）· 退出即焚 · 连按两次 ESC 恐慌关房。
- **前向保密**：文字消息逐条独立密钥（HKDF 棘轮），单条泄露不牵连全会话。
- **定长填充**：密文按固定分桶补齐，隐藏真实消息长度这一元数据。
- **中文房间号 / 口令**：diceware 风格从 704 词的词表无偏抽词，一次生成内**词不重复**；也可切换为纯数字房间号 / 高熵英文口令，或完全自定义。
- **房主入口链接**：房主可复制一条把口令藏在 URL `#` 片段（永不上网）里的自用链接，打开即以房主身份进房——方便复制分享链接后自己重新进入。
- **默契前缀**：可选的私下约定前缀参与 KDF、永不发往 IM/服务器；即便动态口令泄露，缺前缀也无法进房。
- **约定联系时间**：创建时可填一个联系时间，随房间信息一起复制发给对方。
- **终端风音效**：对方接入 / 加密建立 / 收发消息 / 对方离开各有纯 Web Audio 实时合成的提示音（零音频文件、零网络、零存储），状态栏一键静音。
- **移动端一等公民**：响应式布局、虚拟键盘避让、触屏富媒体入口、创建页主操作按钮底部悬浮免滚动。
- **暗网 / 间谍片终端风 UI**：暗底磷光绿、CRT 扫描线、打字机、雪化焚毁 + 燃烧粒子动效。
- **零留痕 / 反爬**：无 localStorage / 无 Service Worker；静态资源 `no-store` 每次重新下载；`noindex` + robots.txt 拒绝搜索引擎与爬虫。

设计详见 [`docs/PRD.md`](docs/PRD.md) 与 [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md)。

## 开发

```bash
npm install       # 安装依赖（npm workspaces monorepo）
npm run dev       # 一键起前端(45273) + 后端 WS(45187)
```

打开 `http://localhost:45273`：

1. 首页填「房间号 + 口令」（可选前缀 / 昵称）→ 点「进入加密房间」。房间不存在则自动创建、已存在则加入。
2. 把同一「房间号 + 口令」带外（微信/当面）发给对方；对方在自己的首页填入同样的号+口令进入，或直接打开分享链接 `http://localhost:45273/<房间号>` 再输口令。
3. 双方号+口令一致 → 完成 ECDH 握手与口令认证 → 进入聊天室，开始端到端加密聊天。

想要高熵随机房间号 / 口令：首页点「随机生成号 / 口令」进入创建页，可自定义房间号 / 口令 / 昵称 / 前缀 / 联系时间，并复制分享链接或「房主入口」链接（含口令、藏在 `#` 后不上网）给自己，日后打开即直接进房。

（本地测试：同一浏览器双开标签即可模拟 A / B。）

## 结构

```
shared/   # 跨端协议类型与常量
client/   # React + Vite 前端（crypto / transport / session / messages / media / ui）
server/   # Node + ws 后端中转（内存房间表，零持久化）
e2e/      # Playwright 端到端测试
deploy/   # nginx.conf 部署示例（静态零缓存 + 反爬 + WS 反代）
```

前端各层职责：

- `crypto/` —— KDF（Argon2id）、ECDH、AEAD、前向保密棘轮、定长填充、安全随机 + 中文词表。
- `transport/` —— WebSocket 客户端（自动重连、帧收发）。
- `session/` —— 会话状态机、握手编排、聊天控制器（`useChat`）。
- `messages/` —— 消息类型与 TTL 定时销毁。
- `media/` —— 富媒体分块 / 加密 / 重组 / 断点续传、时长探测与动态 TTL。
- `ui/` —— 全部界面组件、音效、反截屏、恐慌热键、返回守卫等。

## 部署

把 `client/dist`（`npm run build` 产物）部署到 nginx 的 root，后端 `server` 用 `npm start`（或进程管理器）跑在 45187，参照 [`deploy/nginx.conf`](deploy/nginx.conf)：

- 静态资源 `Cache-Control: no-store` —— 本地不留任何 app 文件（尤其 JS）。
- `X-Robots-Tag: noindex,nofollow,noarchive` + `robots.txt` —— 不被搜索引擎 / 爬虫收录。
- `/ws` 反代到 Node，须传 `X-Forwarded-For`（配置已含）；关闭 access_log（不记录含 roomId 的 URL）。

### 后端环境变量

| 变量 | 作用 |
|------|------|
| `THAW_PORT` | 后端 WS 端口（默认 45187）|
| `THAW_TRUST_PROXY=1` | **反代部署必设**。信任 `X-Forwarded-For` 取真实 IP，否则 IP 限流对所有人都算成 nginx 的 127.0.0.1 而失效 |
| `THAW_ALLOWED_ORIGINS` | 逗号分隔的 Origin 白名单（如 `https://your-domain.example`），防跨站 WS 劫持（CSWSH）。留空则不校验（仅本地开发）|
| `THAW_ALLOW_PROCESS_KILL=1` | 恐慌热键升级为关停整个进程（仅限独占单圈子部署）；默认只销毁本房间 |

### DoS / 滥用防护（内置，针对小众低频场景，阈值偏紧）

- 单 IP 并发连接 ≤ 6；建房 ≤ 3 次 / 分钟；活跃房间 ≤ 3
- 单帧 ≤ 512 KB；帧频率 ≤ 80 帧 / 秒；60s 无 pong 踢死僵尸连接
- 握手失败 5 次 / 分钟 → 销毁房间（防口令在线爆破）
- 阈值定义在 `server/src/ratelimit.ts`，可按需调整

## 安全边界（诚实说明）

雪泥保证「**平台自身看不见、不留档**」，**不保证**「内容从物理世界消失」或「对方一定诚实」。完整威胁模型见 [ARCHITECTURE §11](docs/ARCHITECTURE.md)。

**我们防御的（密码学保证）**：服务器读取内容、服务器 MITM / 掉包公钥、口令在线 / 离线爆破、消息篡改 / 重放、房间劫持、服务器落盘、本地留痕、消息长度元数据（定长填充）。

**我们防不了的（如实告知）**：

- **元数据**：服务器 / 网络可见双方 IP、连接时间、消息时刻与频率、密文大小（长度已定长填充，仅剩分桶粒度）。IP 层需你自行配合 Tor / VPN。
- **前端代码可信性**：这是所有 web E2EE 的根本局限——服务器每次下发前端，理论上可推送被后门的版本。请信任每次下发的前端代码（可自行比对构建产物哈希）。
- **端点安全**：对方截屏 / 拍照 / 录像、设备被入侵，均在密码学范围之外。
- **反截屏是威慑，不是保证**：失焦即糊、PrintScreen 焚毁、隐写水印（溯源）只是抬高成本 + 事后追责，**无法阻止系统截图或另一台手机拍屏**。
- **焚毁靠客户端自觉**：TTL 与退出即焚只对诚实客户端有效；改装客户端可留存明文。

## 加密方案

- **KDF**：Argon2id（WASM，m=64MiB · t=3 · p=1，抗 GPU / ASIC 爆破），salt = SHA-256("thaw:v1:" + 房间号)。WASM 不可用时回退 PBKDF2-HMAC-SHA256（600k 迭代）。默契前缀（若有）参与 KDF 输入。
- **密钥交换**：X25519 的等价实现 ECDH P-256（Web Crypto 原生、全浏览器支持）。
- **会话密钥**：HKDF-SHA256 派生，绑定房间号。
- **消息加密**：AES-256-GCM，递增计数器 nonce，AAD 绑定 roomId + 类型 + msgId + seq（防重放 / 错位 / 跨房间重用）。
- **前向保密棘轮**：文字消息每条用独立、单向推进、不可逆推的 messageKey（HKDF 链）；收发双向各一条链（`a2b` / `b2a`），带跳号缓存容忍乱序。单条密钥泄露只暴露该条，不牵连整个会话。
- **定长填充**：明文按 64 / 256 / 1024 / 4096 字节分桶补齐再加密，隐藏真实长度。
- **口令认证（SAS）**：HMAC-SHA256 短认证串，常数时间比对，防 MITM 掉包公钥。
- **安全随机**：一律 `crypto.getRandomValues`（禁用 `Math.random`）；房间号 / 口令抽词用拒绝采样消除取模偏置。
- 不自造算法，全部基于 Web Crypto 成熟原语。

## 房间隔离与日志

- **房间隔离**：四层保证——服务器只在同房间内转发；房间以 roomId 为键的内存 Map、进程退出即失；会话密钥绑定 roomId；每帧 AAD 绑定 roomId，跨房间密文无法解密。
- **零内容日志**：服务器不记录任何消息内容 / roomId；仅启动时打印一行监听端口。生产 nginx 建议关闭 access_log。
